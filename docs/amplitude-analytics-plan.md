# Amplitude 분석 설계

## 목적

FE 로그는 사용자가 어디서 이탈하는지, 어떤 조건의 유저가 계속 사용하는지, 핵심 행동까지 도달하는지를 보기 위해 남긴다.

우선순위는 다음과 같다.

| 분석           | 목적                                           | 확인 위치 |
| -------------- | ---------------------------------------------- | --------- |
| 성공 지표 분석 | 가설 검증 여부 확인                            | 서버 DB   |
| 코호트 분석    | 리텐션 검증, 며칠째 이탈하는지 확인            | Amplitude |
| 퍼널 분석      | 목표 행동까지의 단계별 전환율과 이탈 지점 확인 | Amplitude |

## 타겟과 가설

타겟은 스크린 타임 제한 앱을 써봤지만 사용 시간 감축에 실패했고, 타인에게 보이는 인증, 기록, 응원이 있을 때 목표를 더 잘 지속하는 사람이다.

가정은 친구에게 스크린 타임을 인증해야 하면 수치심과 책임감 때문에 실제 사용 시간을 줄일 것이라는 점이다.

가설은 타겟 유저가 지인과 그룹을 만들고 인증을 시작했으면, 2주 내 평균 스크린 타임이 감소한다는 것이다.

## 성공 지표

성공 지표는 서버 DB를 기준으로 확인한다. FE 로그는 이 지표의 원인을 해석하기 위한 보조 신호로 사용한다.

| 지표                    | 계산 기준                                                       |
| ----------------------- | --------------------------------------------------------------- |
| 평균 스크린 타임 감소율 | 2주간 스크린 타임 평균 사용 시간 / 처음에 설정한 스크린 타임 값 |
| 스크린 타임 목표 달성율 | 2주간 스크린 타임 평균 사용 시간 / 목표 시간                    |
| 그룹 내 상호작용 수     | 댓글 수, 찌르기 수, 반응 수                                     |
| 그룹 스트릭 유지 날짜   | 그룹 단위 인증 지속성                                           |

## 코호트 분석

Amplitude에서는 사용자가 시간이 지나도 계속 남는지 확인한다.

주요 질문은 다음과 같다.

- 유저들이 며칠 동안 사용하는가?
- 며칠째쯤 재사용 비율이 떨어지는가?
- 방장과 멤버의 리텐션 차이가 있는가?
- 알림 허용 여부에 따라 리텐션 차이가 있는가?

분석 기준은 다음 user property를 사용한다.

| 기준      | Amplitude user property     | 값                |
| --------- | --------------------------- | ----------------- |
| 그룹 역할 | `group_role`                | `OWNER`, `MEMBER` |
| 방장 여부 | `is_leader`                 | `true`, `false`   |
| 알림 허용 | `push_notification_enabled` | `true`, `false`   |

## 퍼널 분석

퍼널 분석은 사용자가 목표 행동까지 가는 단계별 전환율과 이탈 지점을 보는 분석이다.

### 앱 시작에서 그룹 공유까지

앱에 들어온 유저가 그룹을 만들고 공유 버튼까지 도달하는지 확인한다.

| 단계           | 이벤트                        |
| -------------- | ----------------------------- |
| 앱 시작        | `App Opened`                  |
| 인트로 확인    | `Onboarding Viewed`           |
| 그룹 생성 완료 | `Group Created`               |
| 공유 버튼 클릭 | `Invite Share Button Clicked` |

### 초대 참여에서 첫 인증까지

초대코드로 들어온 유저가 목표 설정과 첫 인증까지 도달하는지 확인한다.

| 단계           | 이벤트                   |
| -------------- | ------------------------ |
| 앱 시작        | `App Opened`             |
| 그룹 참여 완료 | `Group Joined`           |
| 목표 시간 저장 | `Goal Time Set`          |
| 인증 완료      | `Verification Completed` |

### 홈 진입에서 일일 인증까지

이미 그룹에 있는 유저가 목표 설정과 일일 인증까지 도달하는지 확인한다.

| 단계           | 이벤트                   |
| -------------- | ------------------------ |
| 홈 진입        | `Feed Home Viewed`       |
| 목표 시간 저장 | `Goal Time Set`          |
| 인증 완료      | `Verification Completed` |

## 로그 설계 원칙

- 이벤트 스키마는 [amplitude-event-schema.md](./amplitude-event-schema.md)를 기준으로 한다.
- 새 로그를 추가하는 방법은 [amplitude-logging-convention.md](./amplitude-logging-convention.md)를 따른다.
- dev/prod 구분은 Amplitude API key와 프로젝트 분리로 처리한다.
- 개인정보와 민감 정보는 Amplitude property에 넣지 않는다.
- API 성공 또는 실제 상태 전환으로 확인할 수 있는 행동은 성공 후 이벤트만 남긴다.
