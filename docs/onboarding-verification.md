# 온보딩 구현 및 검증 결과

검증일: 2026-10-12. 브랜치: `codex/onboarding-flow`.

## 구현 결과

스플래시 → 로그인·약관 → 신규 가입자의 필수 권한 → 앱 선택·즉시 잠금 → 최초 목표 시간 즉시 저장 → 친구 초대를 연결했다. 기존 인증, 잠금 등록, 목표 시간 API, 프로필·공유·검색 기능을 재사용한다. 진행·완료 상태 저장, 중단 복구, 하위 호환 계층은 추가하지 않았다.

목표 시간은 사용자 선택에 따라 시안 A를 적용했다. 이 선택은 [Notion 정책](https://www.notion.so/3f7ad7a38ce581d79883df1f936c5af7)의 Figma 항목에도 반영하고 재조회로 확인했다. 세부 정책과 모듈 연결은 [구현 계획](./onboarding-implementation-plan.md)에 있다.

## 자동 검사와 빌드

- `pnpm quality`: 타입 검사·린트·테스트·포맷 검사 통과. 27개 테스트 파일, 143개 테스트. 린트의 기존 경고 41개는 별도 범위로 유지했다.
- 핵심 회귀: 동의 전 인증 금지, 신규 가입 시 대기 초대 보존, 재로그인 기본 진입, 중복 인증 방지, 권한 거절·설정 복귀·요청 경합, 0분 저장 및 실패 재시도, 중복 저장·앱 등록 방지, 잠금 후 화면 이동, 친구 공유와 대기 목적지 처리.
- iPhone 16 / iOS 18.3 시뮬레이터에서 새 네이티브 빌드 및 설치 성공. Xcode 오류 0개, 경고 11개. 기존 의존성 패치를 설치한 상태에서 iOS 프로젝트를 다시 생성했다.
- 재생성 때 확장 복사 단계와 RNFirebase의 Info.plist 수정 단계가 순환하던 문제는 config plugin으로 해결했다. 네이티브 스플래시 변경을 포함하므로 JS 업데이트만으로 배포할 수 없다.
- 분석 이벤트 검사: 이번 온보딩 이벤트는 문서·타입·호출부가 연결된다. 기존 전체 스키마의 문서 누락 후보 9개와 미사용 후보 3개는 검사 결과에 남겼다. 이번 요청과 무관한 기존 이벤트를 일괄 변경하지 않았다.

## 실제 실행 확인

실제 React Native 앱을 iOS 시뮬레이터에서 실행했다. 인증·프로필·친구 목록·시간 저장의 서버 응답은 런타임에서 로컬 fixture로 대체했다. 실제 서버 가입·친구 요청·목표 변경 성공을 증명하는 E2E 결과는 아니다. 코드에 테스트 전용 라우트나 fixture를 추가하지 않았다.

## Figma UI 동등성

기준은 구현 계획의 실제 Figma 프레임이다. 스플래시, 로그인, 약관 2상태, 권한 2화면, 목표 시안 A, 초대의 8개 화면을 실제 앱 캡처와 나란히 비교하고 overlay와 difference 이미지를 확인했다. 앱 소유 영역의 구성·문구·에셋·정렬을 맞췄으며, 픽셀 전체가 동일하다는 뜻은 아니다.

- 기준: 393×852 Figma PNG. 실제: iPhone 16의 1179×2556 PNG.
- 실제 캡처는 기기의 @3 배율만 393×852로 환산했다. 요소 이동·비율 왜곡·선택 영역 리사이즈는 하지 않았다.
- 원본 전체 비교를 보존했다. 보조 지표인 앱 영역은 양쪽 모두 동일하게 `x=0..393, y=59..818`을 잘라 시스템 상태 표시줄·홈 표시줄을 제외했다.
- RGB 채널 차이가 16을 넘는 픽셀 비율과 평균 절대 채널 오차(0~255)를 기록했다. 수치는 완전 동일 판정이나 기능 테스트의 대체물이 아니다.
- 비교 후 체크박스 라벨, 하단 버튼 글자, 목표 숫자 기준선, 앱 선택 제목·Done 배치 등을 보정했다.

남은 표현 차이:

- Dynamic Island, 상태 표시줄 아이콘·배터리·홈 표시줄은 실제 OS가 그린다. Figma에는 해당 기기의 Dynamic Island가 없다.
- 글자와 벡터 경계의 안티앨리어싱, 체크 표시·약관 화살표 선, 1px 안팎의 버튼 경계 차이가 남는다.
- 앱 선택 프레임은 시스템 스크린샷 위에 제목을 얹은 디자인이다. 실제 iOS 18.3의 밝은 테마 피커는 검색·기본 제목·목록 구성이 다르다. 네이티브 목록을 가짜 목록으로 바꾸거나 OS 외형을 고정하지 않았다. 따라서 앱 선택기 전체 화면의 픽셀 동등성은 미달이며 앱이 소유한 헤더만 정렬했다.
- 작은 화면의 별도 Figma는 없다. 기준 화면의 글자·동작을 유지하며 목표·초대의 여백과 이미지 크기를 줄였다. 본문은 스크롤되고 하단 동작은 고정된다.

## 남은 확인과 애매한 점

제품 정책의 미정 사항은 없다. 다만 다음은 이번 실행에서 검증되지 않았다.

1. 실제 iPhone의 Family Controls 승인·거절·설정 복귀 및 선택 직후 다른 앱에 쉴드가 적용되는지. 시뮬레이터의 권한 fixture와 잠금 모킹 테스트로 대체 판정하지 않는다.
2. 실제 Kakao·Apple 신규 가입, 실서버 0분 저장, APNs 토큰 등록·푸시 수신, 실제 Airbridge 초대 링크를 다른 기기에서 여는 흐름.
3. 배포용 서명·프로비저닝·TestFlight 빌드. 이번 성공은 Debug 시뮬레이터 빌드다.
4. 디자인의 네이티브 피커를 특정 OS·다크 테마로 고정할지. 현재는 기존 피커와 시스템 표현을 유지한다. 이는 새 제품 정책을 임의로 만든 것이 아니며, 추가 디자인 요구가 생기면 별도로 확정한다.

## 검증 자료 위치

저장소 로컬의 `.local/qa/onboarding/`에 원본·검증 자료를 보존했다. 이 폴더는 Git에 포함되지 않으며 현재 작업 환경의 증거다.

- `references/*.png`, `references/sha256.json`: Figma 원본과 해시.
- `actual/*.png`: 실제 시뮬레이터 원본 캡처. `small-*`는 iPhone SE.
- `normalized/*.png`: @3 배율을 환산한 화면.
- `comparison/all-screens.png`: 화면별 기준(왼쪽)·실제(오른쪽) 모음.
- `comparison/*/{side-by-side,overlay,difference}.png`, `metrics.json`, `app-content/`: 전체·앱 영역 비교.
- `quality-final.log`, `ios-build-final.log`, `events-check.json`, `flow-evidence.json`: 검사·빌드·이벤트·fixture 요청 증거.
- `compare-final.py`, `runtime*.mjs`, 각 fixture JS: 비교 및 런타임 검증 재현 자료. 제품 코드에는 포함하지 않는다.

재현 시 실서버 검증과 로컬 fixture 검증을 혼동하지 않는다. Figma를 바꾸지 않고 실제 앱을 다시 캡처해 비교한다.

검증 종료 후 작업용 iPhone SE 시뮬레이터를 종료·삭제하고 직접 실행한 Metro 서버를 종료했다. iPhone 16의 런타임 fixture는 앱 종료로 제거했으며 다른 시뮬레이터는 종료하지 않았다. 재생성 전 iOS 프로젝트는 `.local/qa/onboarding/ios-before-regenerate/`에 보존했다.
