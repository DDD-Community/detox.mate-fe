# 온보딩 개편 구현 계획

작성일: 2026-10-12

상태: 정책 및 구현 방향 확정. 추가 정책 인터뷰는 종료했다. 2026-10-12 Figma의 실제 온보딩 프레임 10개를 확인하고 아래에 연결했다. 구현을 진행 중이다. 목표 시간은 사용자 선택에 따라 시안 A(변경 가능 안내 포함)를 적용한다.

## 1. 목표와 합의한 흐름

기존 인증·권한·앱 잠금·친구 기능을 재사용해 새 온보딩을 연결한다. 비슷한 화면은 컴포넌트 책임 단위로 공유하며 범용 온보딩 프레임워크는 만들지 않는다.

스플래시 → 로그인 화면 → 약관 동의 → 소셜 인증 → 스크린타임 권한 → 알림 권한 → 잠글 앱 선택 → 목표 시간 설정 → 친구 초대

사용자가 확인한 정책:

- 약관 동의 후 소셜 인증하는 기존 순서를 따른다. 로그인 화면에서 선택한 수단으로 동의 후 인증한다.
- 새 온보딩은 신규 가입자에게만 시작한다.
- 온보딩 완료 여부·진행 단계는 기기나 서버에 기록하지 않는다. 중단 후 재실행·재로그인 시 온보딩으로 되돌리거나 이어서 진행하지 않는다.
- 약관을 열람하고 앱으로 돌아오면 해당 항목을 자동으로 체크하는 현재 동작을 유지한다.
- 기존 사용자는 없앨 예정이므로 이전 버전 사용자·데이터와의 하위 호환은 고려하지 않는다. 호환 분기·마이그레이션·예전 그룹/피드 기본 진입 경로를 유지할 필요가 없다. 실제 사용자 삭제 작업은 이 계획의 실행 범위가 아니다.
- 스크린타임·알림 권한은 모두 필수다.
- 알림 권한 허용 후 푸시 토큰 등록이 실패해도 기존처럼 진행한다. 등록 실패 기록·재시도는 기존 경로를 사용한다.
- 온보딩 완료 이후 사용자가 권한을 끄더라도 온보딩으로 돌려보내거나 앱 진입을 차단하지 않는다. 이후 화면의 기존 권한 설정 기능을 사용자가 이용하도록 두며, 이번 작업에서 재허용 강제 흐름을 추가하지 않는다.
- 잠글 대상은 하나 이상 선택해야 한다.
- 앱 선택 완료 즉시 잠근다. 목표 시간 저장이나 온보딩 종료까지 잠금을 미루지 않는다.
- 최초 목표 시간은 0시간이며, 기존 0~4시간·1시간 단위를 유지한다.
- 목표 시간의 ‘완료’를 누르면 바로 저장하고 친구 초대로 이동한다. 온보딩에는 기존 다짐·카운트다운 화면을 넣지 않는다.
- 친구 초대에서 코드 복사·프로필 공유 후에는 화면에 머문다.
- ‘건너뛰기’는 제한 앱 탭으로 이동하며 온보딩을 끝낸다.
- ‘친구 코드로 추가하기’는 친구 탭의 기존 검색으로 이동하며 온보딩을 끝낸다.

여기서 온보딩 종료는 화면 흐름의 종료를 뜻하며, 별도의 완료 상태 저장이나 완료 API 호출은 없다.

첨부된 목표 시간 화면 두 장에 대응하는 Figma 프레임을 각각 확인했다. 동일 단계의 두 시안으로 구분했으며 차이와 링크는 6절에 기록했다. 구현 시 상세 디자인과 에셋을 해당 프레임에서 확인한다.

## 2. 기존 모듈 재사용과 변경 범위

| 단계            | 참고·재사용할 모듈                                                           | 변경 내용                                                                                     |
| --------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 스플래시        | `SplashScreen`, 네이티브 스플래시 설정                                       | 새 디자인 반영, 인증 여부에 따른 로그인·메인 진입 정리. 온보딩 진행 상태 조회는 추가하지 않음 |
| 로그인          | `LoginScreen`, `AuthLoginButton`, `useAuthLogin`, `TestLoginTrigger`         | 새 화면 구성, 약관과 인증 연결. 로그인 실패 안내·중복 실행 방지·테스트 로그인 기능 유지       |
| 약관            | `TermsAgreementRow`, `useTermsAgreement`, 기존 약관 URL                      | 로그인 화면 위 시트로 구성. 동의 상태 관리와 화면 이동 책임 분리                              |
| 스크린타임 권한 | `SelectAppsScreen`의 권한 확인·요청 코드                                     | 별도 안내 단계에서 권한 요청. 기존 앱 선택 진입의 권한 확인도 유지                            |
| 알림 권한       | `useAuthLogin`의 알림 요청, `registerDevicePushToken`                        | 별도 안내 단계로 이동. 허용 후 기존 푸시 토큰 등록 실행                                       |
| 앱 선택         | `SelectAppsScreen`, `lockStore`, `lockRegistration`, 토큰 조합·분리 모듈     | 네이티브 피커와 잠금 등록을 재사용하고 온보딩의 다음 단계 연결                                |
| 목표 시간       | `GoalTimeScreen`, `GoalTimeConfirmScreen`의 저장 처리                        | 입력 카드를 공유하고 온보딩에서는 완료 즉시 저장                                              |
| 친구 초대       | `useMyProfile`, `useShareFriendInvite`, `ClipboardCopyToast`, 기존 친구 검색 | 내 코드 표시·복사, 프로필 공유, 친구 검색 진입을 조합                                         |

현재 코드에서 확인한 사항:

- 기존 진입 순서는 소개형 온보딩 → 약관 → 로그인이다.
- 로그인 후 기존 접근 권한 안내에서 갤러리·알림 권한을 함께 요청한다.
- 로그인과 스플래시의 기본 목적지는 기존 그룹·피드 화면이다.
- 앱은 선택을 등록하는 시점에 즉시 잠긴다. 목표 시간 도달 시 처음 잠기는 구조가 아니다.
- 목표 시간은 현재 기본 120분이며, 별도 확인 화면에서 서버 저장 후 로컬 값을 갱신한다.
- 기존 시간 설정 API는 `PUT /me/time-limit`이고 `totalLockMinutes`는 생성 타입상 0~1440분을 허용한다.
- 친구 공유의 링크용 `code`와 표시·검색용 `userCode`는 서로 다른 값이다.
- 기존 인증 후 이동은 알림 → 대기 초대 → 기본 목적지 순서다.

기존 소개형 `OnboardingScreen`과 로그인 후 갤러리·알림 통합 안내는 새 진입 흐름에서 교체한다. 갤러리 권한은 실제 사진 사용 기능의 요청 경로를 유지한다. 예전 그룹·피드 기능 전체 삭제는 범위에 포함하지 않는다.

## 3. 컴포넌트와 기능의 책임

- `OnboardingLayout`: 안전 영역, 본문, 하단 버튼 영역을 배치한다. 단계 전환이나 API 호출은 소유하지 않는다.
- `PermissionGuide`: 제목·설명·안내 이미지·버튼을 표시한다. 실제 권한 처리는 각 화면이 담당한다.
- `GoalTimeCard`: 시간 값과 증감 동작을 받는다. 온보딩과 기존 목표 변경 화면에서 공유하고 저장·이동은 호출 화면이 담당한다.
- `TermsAgreementSheet`: 기존 동의 행과 체크박스를 조합한다. 선택한 로그인 수단과 인증 실행은 로그인 화면이 관리한다.
- 앱 선택의 토큰 처리·잠금 등록은 한 구현으로 유지한다. 완료 후 이동만 호출 경로에 맞게 연결한다.
- 목표 시간 저장은 기존 API와 `confirmTargetMinutes`를 사용한다. 공유하는 저장 작업만 분리하고, 저장 후 목적지는 각 화면이 결정한다.
- 내 코드는 `useMyProfile`의 `userCode`를 사용한다. 공유는 기존 `useShareFriendInvite`를 재사용한다.
- 공유 취소·실패 시 친구 초대 화면에 머문다.
- 범용 단계 엔진, 화면 설정 DSL, 새로운 상태 관리·UI 라이브러리는 추가하지 않는다.

서버 API 변경은 계획하지 않는다. 필요한 인터페이스 변경은 표시 컴포넌트의 값·콜백, 앱 선택 기능의 완료 연결, 친구 검색 진입 시 입력창 포커스를 요청하는 최소 라우트 인자로 제한한다.

## 4. 진입·중단·실패 처리

### 진입과 중단

- 미로그인으로 시작하면 로그인 화면으로 이동한다. 필요한 약관 동의 후 선택한 소셜 인증을 실행한다.
- 로그인 응답의 `isNewUser`가 참이면 그 로그인 흐름에서 새 온보딩을 시작한다. 거짓이면 기존 인증 후 이동 처리를 실행하고 기본 목적지는 제한 앱 탭으로 둔다.
- 인증된 상태로 앱을 다시 시작하면 온보딩 진행 여부를 조회하지 않고 메인으로 이동한다. 대기 알림·초대가 있으면 기존 목적지 처리 규칙을 따른다.
- 로그인 후 온보딩을 중단해도 재실행·재로그인 시 되돌리지 않는다. 새 기기·재설치에서도 온보딩 복구를 위한 기록·동기화·별도 분기를 추가하지 않는다.
- 권한 승인·앱 등록·목표 시간 저장처럼 이미 적용된 결과는 유지한다. 온보딩 중단을 이유로 잠금을 해제하거나 저장값을 되돌리지 않는다.
- 목표 시간 설정 전에 중단했다면 0시간을 자동 저장하지 않는다. 0시간은 최초 입력 화면의 시작값이며, 실제 저장은 사용자가 ‘완료’를 눌렀을 때만 한다.
- 현재 실행 중인 화면의 입력·단계 상태만 관리한다. 완료 플래그, 진행 체크포인트, 온보딩 복구용 store·서버 필드는 만들지 않는다. 기존 약관 동의 이력은 온보딩 완료 기록과 별개로 유지한다.

### 권한과 저장

- 진행 중인 온보딩에서는 스크린타임·알림 권한을 모두 허용해야 앱 선택으로 넘어간다. 이는 해당 흐름의 다음 단계 조건이며, 재실행 시 메인 진입을 막는 전역 조건이 아니다.
- 버튼으로 시스템 권한을 요청한다. 거절하면 해당 안내 화면에 머물고, 재요청할 수 없으면 설정 이동을 안내한다. 해당 화면으로 복귀할 때 권한을 확인하며 이미 허용된 권한은 다시 요청하지 않는다.
- 온보딩 이후 권한을 끈 경우에는 사용자가 이후 화면의 기존 권한 설정 기능을 이용하도록 둔다. 온보딩 복귀나 전역 진입 차단을 추가하지 않는다.
- 알림 권한 허용과 서버 푸시 토큰 등록 성공은 구분한다. 등록 실패는 기존처럼 온보딩을 막지 않으며 기존 기록·재시도 처리를 사용한다.
- 앱 선택의 ‘Done’은 유효한 선택이 하나 이상일 때 진행할 수 있다. 선택 등록과 동시에 잠근다.
- 목표 시간은 서버 저장 성공 후 로컬·공유 설정을 갱신하고 친구 초대로 이동한다. 실패하면 화면과 선택값을 유지해 재시도할 수 있게 하며 저장 중 중복 실행을 막는다.
- 기존 목표 시간 변경 화면의 확인 절차는 유지한다. 온보딩의 즉시 저장 정책을 목표 변경에 확대 적용하지 않는다.

### 친구 초대와 외부 진입

- 내 코드 복사·프로필 공유는 친구 초대 화면에 머무르는 동작이다. 공유 완료·취소·실패만으로 다음 화면으로 이동하지 않는다.
- ‘건너뛰기’의 기본 목적지는 제한 앱 탭이고, ‘친구 코드로 추가하기’는 친구 탭의 기존 검색이다. 별도의 온보딩 전용 친구 검색·요청 기능은 만들지 않는다.
- 로그인 전에 받은 초대·알림은 기존 대기 처리 기능으로 보존한다. 신규 가입의 일반 흐름에서는 로그인 직후 목적지 이동으로 온보딩을 자동 생략하지 않고, 종료 시 기존 인증 후 이동 처리를 연결한다.
- 대기 목적지가 있으면 기존 알림 → 초대 → 기본 목적지 우선순위를 유지한다. 없으면 종료 버튼에 따른 기본 목적지로 이동한다.
- 온보딩 도중 외부 링크·알림으로 이동하거나 앱을 재시작한 경우에도 온보딩으로 되돌리는 보호·복구 흐름은 만들지 않는다. 이전 계획의 ‘미완료 온보딩 우회 방지’ 제안은 적용하지 않는다.

## 5. 구현 순서와 검증

1. 6절에 연결한 Figma에서 화면별 스타일·에셋을 확인하고 목표 시간의 최종 시안을 정한다.
2. 로그인·약관과 신규 가입 분기를 연결하고 기존 소개·통합 권한 안내를 교체한다.
3. 공통 배치와 권한 안내를 구성하고 실제 시스템 권한 요청을 연결한다.
4. 기존 앱 선택·잠금 등록과 목표 시간 입력·저장을 연결한다.
5. 친구 초대와 종료 화면 이동을 구성하고 재실행·초대·알림 진입을 점검한다.

자동 검증은 기존 인증·초대 테스트를 수정하고 다음 불변식에 집중한다.

- 신규 가입 로그인에서 온보딩을 시작하되, 중단 후 재실행·재로그인으로 온보딩에 복귀하지 않는다.
- 진행 중인 온보딩에서 필수 권한·앱 선택 조건을 충족하기 전에는 다음 단계로 넘어가지 않는다. 이후 권한 철회로 앱 진입을 차단하지 않는다.
- 목표 시간 저장 실패 시 화면과 선택값을 유지하고, 중복 클릭으로 저장이 중복되거나 저장 성공 전에 다음 화면으로 이동하지 않는다.
- 대기 초대·알림을 보존하고 기존 목적지 우선순위를 유지한다. 중단한 온보딩으로 되돌리지 않는다.

이전 버전 사용자 호환 테스트, 완료 상태 영속화·단계 복구 테스트, 단순 화면별 렌더링 테스트는 추가하지 않는다.

구현 후 타입 검사·린트·관련 테스트·포맷 검사를 수행한다. 실제 iPhone에서는 권한 거절 후 설정 복귀, 네이티브 앱 선택과 잠금, 0시간 저장, 공유 취소, 중단 후 재실행을 확인한다. 화면 배치는 작은 화면·안전 영역·친구 검색 키보드까지 Figma와 대조한다.

## 7. 작업 범위

정책 인터뷰는 사용자 확인으로 종료했다. 정책 위키와 로컬 구현 계획에 화면별 Figma 링크를 연결했다. 앱 코드·서버·사용자 데이터·Figma 원본은 변경하지 않았다.
